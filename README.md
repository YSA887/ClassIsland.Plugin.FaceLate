# 人脸早读考勤 · ClassIsland 插件

在 ClassIsland 2.x 上运行的**班级人脸考勤插件**：到设定的早读时间点自动用摄像头连拍多张照片，
调用本地开源轻量人脸模型（YuNet + SFace）自动比对学生人脸库，按花名册找出**迟到的同学**，
并在主界面组件上显示迟到名单和考勤明细。

全部推理都在本机 CPU 上完成，**不联网、不上传任何照片和特征**。

| 需求 | 实现方式 |
| --- | --- |
| 录入班级人脸 | 「人脸花名册」设置页：逐个同学录入，支持**反复多次录入**（不同角度 / 光线 / 戴不戴眼镜），样本自动累积 |
| 批量导入照片 | 文件名里带人名（`806班A.jpg`）时自动匹配到对应同学，整批一次导入并给出汇总 |
| 智能导入照片 | 库里已有样本时逐张询问「这是 XXX 吗」，确认即入库，不用手动挑人 |
| 多种录入来源 | 摄像头连拍录入；也可以直接选已有照片（证件照、活动照）批量录入 |
| 早读识别迟到 | 定时器在设定时间自动触发一次完整考勤流程；**按星期分别设置**，每天可配多个时刻 |
| 挂到自动化规则集 | 提供行动「人脸考勤：执行一次考勤」，晚自习等临时场景直接在自动化里挂规则 |
| 设置界面清晰 | 设置页按功能分成 5 个页面 + 分组菜单，不再一层铺满 |
| 运行日志不碍事 | 分级日志面板默认折叠，细节行可一键展开，出问题再翻开看 |
| 摄像头抓拍多张 | 可配置张数（默认 4 张）与间隔（默认 400 ms） |
| AI 多次自动比对 | 每张照片都做一次「检测 → 特征提取（SFace 128 维 / ArcFace 512 维）→ 与人脸库逐个比对」，同一位同学需在 ≥ N 张照片中命中才算被识别到（投票机制，抗单帧误判） |
| 按花名册找出迟到的人 | 命中人数与花名册（排除请假 / 不参与考勤的同学）做差集或交集 |
| 显示迟到人的组件 | 「早读迟到名单」组件，可拖到主界面任意位置 |
| 开源小模型、8 GB 可跑 | OpenCV Zoo 的 YuNet（230 KB）+ SFace（37 MB），纯 CPU，常驻内存约 100~200 MB；也可换成体积更小的 ArcFace（13 MB） |
| 模型随包发布、**不需要联网** | 两个模型都打包在 `.cipx` 里，插件优先从**自己所在目录**加载；也可以手动导入 .onnx（U 盘拷进来即可），默认关闭联网下载 |
| 抓拍时间精确到秒 | 支持 `07:20:30` 这种写法，定时器每秒检查一次 |
| 2 分钟内完成 | 实测流程 3 秒左右（1280×720、4 张）；另有「耗时上限」硬超时保护（默认 100 秒） |
| 执行过程可见 | 设置页有真正的进度条 + 阶段文字，识别到哪一步一目了然 |

## 二、技术选型

### 人脸模型

| 模型 | 文件 | 大小 | 说明 |
| --- | --- | --- | --- |
| **YuNet**（检测） | `face_detection_yunet_2023mar.onnx` | ≈ 230 KB | 毫秒级轻量人脸检测，输出人脸框 + 5 个关键点 + 置信度。[OpenCV Zoo](https://github.com/opencv/opencv_zoo)，Apache-2.0 |
| **SFace**（识别，默认） | `face_recognition_sface_2021dec.onnx` | ≈ 37 MB | 输出 128 维特征，官方推荐余弦阈值 **0.363**（对应 NORM_L2 阈值 1.128）。[OpenCV Zoo](https://github.com/opencv/opencv_zoo)，Apache-2.0 |
| **ArcFace / MobileFaceNet**（识别，可选） | `w600k_mbf.onnx` | ≈ 13 MB | 输出 512 维特征，精度更高、体积更小，见下方对比。**推荐余弦阈值 0.50**（与 SFace 的 0.363 不是一回事）。来自 [InsightFace](https://github.com/deepinsight/insightface) 的 `buffalo_sc` 包 |

> ⚠️ **阈值是每款模型各自的，不能共用一个数**。余弦相似度的分布随模型结构、训练集、损失函数而变，
> InsightFace 官方指南里也写着「never carry over a threshold across model versions」。
> 插件会把每款模型的阈值分开保存，切换模型时自动用该模型的推荐值（设置页可手动微调，并有一键恢复）。

**两个识别模型的实测对比**（同一张 2048×1150 的 34 人合影，按默认设置缩到 1280×720，最小人脸 60 px，对亮度 +10 / JPEG q60 的扰动重算最近邻相似度）：

| 指标 | SFace（默认） | ArcFace w600k_mbf |
| --- | --- | --- |
| 模型体积 | 37 MB | **13 MB** |
| 特征维度 | 128 | 512 |
| 载入耗时 | ~40 ms | ~41 ms |
| 单帧耗时（1280×720） | ~71 ms | ~96 ms |
| 同一张脸跨扰动的余弦 | 0.9372 ~ 0.9562 | 0.9207 ~ 0.9725 |
| **不同人之间的最大余弦** | 0.3186 | **0.2673**（更好） |
| 判定余量（越低越危险） | 0.6186 | **0.6534** |

结论：**默认用 SFace**（Apache-2.0 可自由分发、速度更快）；想再稳一点可以换 ArcFace，
它的区分度略好、文件还小 2/3，代价是单帧慢约 25 ms。
> ⚠️ **许可提醒**：InsightFace 的模型标注为「仅供非商业研究用途」。校内教学使用属于非商业场景，
> 但如果要把插件公开发布，建议保留自带的 SFace（Apache-2.0）而不要打包 ArcFace。
> 因此本插件**没有把 ArcFace 打进安装包**，需要用的同学请自行导入。

模型合计不到 40 MB，纯 CPU 推理，任何 8 GB 内存的教室电脑都绰绰有余。
**两个默认模型都已经打包在 `.cipx` 里**，安装后开箱即用，不需要联网。

### 推理与采集

- **OpenCvSharp4 / OpenCvSharp4.runtime.win 4.13**：`VideoCapture` 采集摄像头，`FaceDetectorYN`（YuNet）检测，`CvDnn` 跑 SFace 提取特征。
- 摄像头打开顺序：DirectShow → MSMF → 自动，兼容各类 USB / 笔记本内置摄像头。
- 图像编解码自己走 `ImEncode` + `File.WriteAllBytes`，避免中文路径在 Windows 上写不出去。

> **为什么不用 OpenCV 自带的 `FaceRecognizerSF`？**
> OpenCvSharp 4.13 只封装了 `FaceDetectorYN`，还没有封装 `FaceRecognizerSF`
> （它是 OpenCV 4.14 才进入 OpenCvSharp 的）。所以本插件用 `CvDnn` 直接加载 SFace 的 ONNX 模型，
> 并**按 OpenCV 官方 `modules/objdetect/src/face_recognize.cpp` 的实现，自己写了对齐逻辑**
> （5 点关键点 + Umeyama 相似变换 → 112×112，`blobFromImage(scale=1, swapRB=true, crop=false)`）。
> 这样得到的 128 维特征与官方实现一致，SFace 官方推荐的 0.363 阈值在本插件里同样成立。
> （换用 InsightFace 系模型时预处理不同，阈值也用该模型自己的推荐值，见 [CHANGELOG 的 v1.2.1](CHANGELOG.md#v121修正阈值0363-是-sface-的不是-arcface-的)。）

### 匹配算法

```
对每一张抓拍照片：
    检测出画面中所有人脸（丢弃置信度 < 0.7 或宽度 < 40px 的）
    对每张脸提取 128 维特征
    与人脸库中所有样本计算余弦相似度，取最高分
    若最高分 >= 阈值，则该脸归属这位同学，给这位同学记 1 次命中（同一张照片只记 1 次）

汇总：
    命中次数 >= 「最少命中张数」的同学 = 被识别到（在教室里）
```

余弦相似度按 `dot(a,b) / (|a|·|b|)` 在 C# 里直接计算，与 OpenCV `FaceRecognizerSF::match(FR_COSINE)`
（先 L2 归一化再点积）的算法完全一致，避免为每次比较构造原生 Mat。

### 两种判定方式

- **教室抓拍 · 缺席判定（默认）**：摄像头对着教室，在早读开始时刻抓拍。
  `迟到 = 花名册（应到） − 被识别到的人`。最贴近「早读抓拍看谁还没来」的场景。
- **门口抓拍 · 出现判定**：摄像头对着门口/走廊，在早读开始之后的时间点抓拍。
  `迟到 = 被识别到的人`。

> 两种方式下，**已请假**和**未录入人脸**的同学都不会被误判为迟到：
> 请假同学直接排除；未录入人脸的同学不参与判定，并在结果备注里列出姓名提醒老师补录。

## 四、编译

### 环境要求

- **.NET SDK 8.0**（ClassIsland 2.0.x ~ 2.1.0.x 使用 .NET 8）
- Windows（本插件依赖 OpenCvSharp 的原生库；ClassIsland 本体也主要跑在 Windows）
- PowerShell 7（`pwsh`）：用于生成 `.cipx` 包中的 MD5 摘要，没有的话可以设置 `<GenerateHashSummary>false</GenerateHashSummary>`

> 如果你用的是 **ClassIsland 2.1.1 及以上**（那一版起 ClassIsland 升到了 .NET 10），
> 请把 csproj 里的 `<TargetFramework>` 改成 `net10.0`，
> 并把 `<ClassIslandPluginSdkVersion>` 改成 `2.1.1.1` 或更高。

### 步骤

```powershell
# 1. 下载模型（约 37 MB，编译时会一起打包；不下载也能跑，插件首次运行会自动下载）
pwsh -File tools/download-models.ps1

# 2. 编译，并自动生成 .cipx 插件包
dotnet build -c Release

# 产物：
#   bin/Release/net8.0/ClassIsland.Plugin.FaceLate.dll  ... 插件本体
#   cipx/ClassIsland.Plugin.FaceLate.cipx               ... 可直接安装的插件包
```

## 五、安装到 ClassIsland

> **最快的方式**：直接用已经编译好的插件包 `ClassIsland.Plugin.FaceLate.cipx`（109 MB，已包含模型和 OpenCV 运行时），
> 不需要装 .NET SDK、也不需要自己编译。

1. 打开 ClassIsland →【应用设置】→【插件】→【从本地安装】，选择 `ClassIsland.Plugin.FaceLate.cipx`；
   或者直接把 `.cipx` 文件丢进 ClassIsland 的插件包目录后重启应用。
2. 重启 ClassIsland，在【应用设置】→【插件】里确认「人脸早读考勤」已启用。
3. 进入【应用设置】，左侧「扩展」分组下会出现两个新页面：**人脸早读考勤**、**人脸花名册**。

> 安装后请确认插件目录下存在 `OpenCvSharpExtern.dll` 与 `opencv_videoio_ffmpeg4130_64.dll`
> 这两个原生库（本项目的构建脚本会自动从 `runtimes/win-x64/native/` 拷到输出根目录）。
> 缺少它们时插件会提示「找不到 OpenCV 原生库」。

## 六、使用流程

### 1. 录入花名册

【应用设置】→【人脸花名册】：

- 填好「班级名称」，然后在左侧输入姓名逐个添加；
  或者点 **导入花名册文本…** 选择一个 `.txt` / `.csv`（每行一位同学，支持 `姓名,班级` 两列），
  也可以先把名单复制到剪贴板再点 **从剪贴板导入**。
- 名单形如：

  ```
  张三
  李四,高二(3)班
  王五,高二(3)班
  ```

### 2. 录入人脸（可多次，越录越准）

在左侧选中一位同学，然后把摄像头对准他：

| 按钮 | 说明 |
| --- | --- |
| **摄像头录入** | 按设定的张数连拍，每张挑画面中最大的一张脸存成一条样本。建议**分 2~3 次录入**：正脸一次、稍微左右侧脸各一次、戴眼镜再录一次。 |
| **从图片文件录入…** | 选一张或多张已有照片批量录入，一张照片里的多张脸会分别存成样本。 |
| **删除选中样本** / **清空该生全部人脸** | 录错了可以逐条删除或整体清空。 |

每位同学最多保留 12 条样本（超出后自动淘汰最早的），经验上 **4~8 条**就足够稳定。
录入时右下角会实时显示摄像头画面，方便确认人在画面里的位置。

### 3. 配置考勤

【应用设置】→【人脸早读考勤】：

- **每天抓拍时间**：例如 `07:20`（24 小时制）。
- **补执行窗口**：ClassIsland 在抓拍时间之后才启动时，仍会在窗口期内补做一次（默认 30 分钟）。
- **迟到判定方式**：教室抓拍·缺席判定 / 门口抓拍·出现判定。
- **摄像头**：序号（默认 0，外接 USB 摄像头一般是 1）、分辨率（640×480 足够）、张数、间隔、预热秒数。
- **识别参数**：相似度阈值（按当前模型取推荐值 —— SFace 是 0.363、ArcFace 是 0.50，可手动微调并一键恢复）、最少命中张数（默认 2）、流程耗时上限（默认 100 秒）。
- **抓拍存档**：是否保留抓拍照片、保留天数。
- 建议先点 **测试摄像头** 确认能出画面，再点 **立即识别一次** 跑一遍完整流程看效果。

### 4. 把组件拖到主界面

【应用设置】→【组件】→ 组件库里找到 **早读迟到名单**，拖到主界面上。
可以在组件的设置里改标题、是否在没迟到时隐藏、上课时是否自动隐藏、名单最多显示几人等。

组件显示效果大致是：

```
早读迟到                                        [3 人]
张三、李四、王五
识别完成，迟到 3 人（6.4 秒）
识别时间 07:20:03 · 抓拍 4 张 · 检测到 38 张脸 · 耗时 6.4 秒
```

## 七、耗时与性能

下面是**实测数据**（普通办公 PC，CPU 推理）。测试图是一张 2048×1150 的 34 人合影，
按插件的默认设置缩放到 **1280×720** 后推理：

| 项目 | 实测值 |
| --- | --- |
| SFace 模型载入 + 检测器创建 | ≈ 40 ms |
| 首次推理（含内存分配预热） | 58 ms |
| 1280×720 单帧「检测 + 逐张脸特征提取」 | **≈ 71 ms**（该帧检出 5 张合格人脸） |
| 8 张脸 × 200 条样本的余弦比对 | 1 ms |

按 40 人班级、1280×720、抓拍 4 张估算：

| 阶段 | 耗时 |
| --- | --- |
| 打开摄像头 | ≈ 1 s |
| 预热 | 1 s（可设为 0） |
| 连拍 4 张 | ≈ 1.6 s |
| 检测 + 特征提取（4 帧 × 约 70 ms） | ≈ 0.3 s |
| 与人脸库比对（约 40 张脸 × 200 条样本） | ≈ 0.05 s |
| **合计** | **约 3 秒** |

内存占用：两个模型合计不到 40 MB，常驻 + 推理峰值约 100~200 MB，8 GB 内存毫无压力。
即使把抓拍张数拉到 20 张，量级也在 15 秒以内，远低于 2 分钟的要求。
另外插件有**硬超时**：一旦超过设置页里的「流程耗时上限」（默认 100 秒）会立即中止本次识别并在界面给出提示。

### 640×480 到底够不够准？——实测答案是"不够"

同一个场景、同一张测试图，只改抓拍分辨率的对比（阈值取 **SFace 的 0.363**；
相似度用「最近邻匹配」计算，即扰动前后取最高余弦，而不是按下标配对——扰动后检测框顺序会变）：

| 抓拍分辨率 | 最小人脸 | 合格人脸 | 同脸跨扰动余弦 | **异脸最大余弦** | 与阈值 0.363 的余量 |
| --- | --- | --- | --- | --- | --- |
| 640×480 | 40 px | 2 张 | 0.9010 | **0.3593** ⚠️ | **0.0007**（几乎为零） |
| **1280×720** | **60 px** | **5 张** | 0.9372 | **0.3186** ✅ | **0.0444** |

640×480 下「不同人之间的最大余弦」是 0.3593，而判定阈值是 0.363——**只差 0.0007**，
等于说随便两张脸都有可能被误判成同一个人；同时只有 2 张脸够大能被识别，后排同学基本没参与判定。
换成 1280×720（并把最小人脸从 40 px 提到 60 px）之后，异脸最大余弦降到 0.3186、余量拉开到 0.0444，
合格人脸也从 2 张增加到 5 张。

**结论：640×480 不是"够用"，而是"勉强不炸"**——这正是 v1.0.0 后排同学认不出来的根本原因，
问题不在模型，在像素。**想认准，先把分辨率提上去，这比换模型管用得多**；
换 ArcFace 只是在此基础上再多一点余量（异脸最大余弦 0.3186 → 0.2673）。

## 八、常见问题

**打不开摄像头 / 一直失败**
1. 先点设置页的「测试摄像头」，换序号（0、1、2…）试；
2. 确认没有其它程序（钉钉、腾讯会议、相机 App）占用摄像头；
3. 笔记本内置摄像头 + 外接 USB 摄像头同时存在时，序号会变，逐个试一遍。

**总是把某位同学判成迟到**
- 大概率是他的人脸样本太少或角度太单一 → 多录几次；
- 也可能是抓拍时他背对摄像头/被挡住 → 适当增加抓拍张数；
- 或者相似度阈值太高 → 从 0.363 适当下调到 0.32 试试（设置页可调）。

**把别人认成了这位同学（串脸）**
- 阈值太低 → 在推荐值基础上上调（SFace 试 0.40~0.45，ArcFace 试 0.55~0.65）；
- 把「最少命中张数」提到 3，配合 5~6 张抓拍。

**导入花名册后有些人没参与判定**
- 他们还没有录入人脸。结果备注里会列出这些同学的名字。

**报 `Call from invalid thread`，插件被 ClassIsland 自动禁用了**
- 这是 v1.0.0 的 bug：识别在后台线程跑，却直接改了界面控件。**v1.0.1 已修复。**
- 升级后如果仍被禁用，到【应用设置】→【插件】里重新启用，再重启一次即可。

**录入人脸时明明人脸很清楚，却提示「未检测到人脸」**
- v1.1.0 及以前的 bug：检测器不会自动缩放输入，**任何尺寸和它创建尺寸不一致的图片都会检测失败**，
  失败被转成了「未检测到人脸」→ 竖版照片（手机拍的、证件照）、俯拍摄像头画面首当其冲。**v1.2.0 已修复**，
  现在会自动按原图比例缩放检测，横版 / 竖版 / 方形都能检出。
- 升级后如果还是不行，把「最小人脸像素」调小一点（默认 60）——**照片里人脸本身小于这个像素数**也会被过滤掉，
  这种情况提示里会写清楚是「过滤掉了」而不是「没检测到」。
- **换一台电脑就每一张都失败？**（尤其是教室一体机）**v1.2.3 已修复**：那是模型路径含中文
  （Windows 用户名是中文，或 ClassIsland 装在 `D:\教学软件\...` 这类目录）导致 OpenCV 读不出检测模型，
  异常被吞成了「未检测到人脸」。现在插件会自动把模型复制到纯 ASCII 目录再加载。
  升级后如仍失败，请到「识别与模型」页看**自检**那一行——它会直接说明病因；
  同时「运行日志」里会有一条错误记录，把它发出来即可定位。

**一张照片/一帧画面里有好几个人，想录指定的那一个**
- v1.2.0 新增：多张脸时会弹出**带编号方框的预览图** + 每张脸的缩略图，点一下就录你选的那张。
  照片录入还会顺带标出「这张脸最像谁」，方便确认没认错人。
- 一帧里只有一张脸时不会打扰你，直接录。

**提示「模型无法加载」/ 明明有模型却一直下载**
- v1.0.0 会用 ClassIsland 主程序目录去找模型，永远找不到 → 触发下载。**v1.0.1 已修复**，
  现在优先从插件自己的目录加载随包模型，且**默认关闭联网下载**。
- 如果确实缺模型：到【人脸早读考勤】设置页点「**导入模型文件…**」，选中 .onnx 文件即可
  （插件会自动复制到自己的模型目录）。也可以点「检查模型状态」看它到底在哪些位置找过。
- 学校网络访问不了 GitHub / HuggingFace，所以请在能上网的电脑上下好文件，用 U 盘拷过来。

**后排同学总是认不出来（或反过来认错）**
1. **先把抓拍分辨率提到 1280×720 以上**——这是最有效的一步（见第七节的实测对比）；
2. 确认摄像头对焦在整个教室，而不是只对着前排；
3. 「最小人脸像素」保持默认 60 左右；调到 40 会捞回一些后排小脸，但误判风险明显上升；
4. 给后排同学额外录入几次人脸（可以拿手机拍正脸照，用「从照片录入」）；
5. 还不行就把阈值从推荐值往上调（SFace 0.363 → 0.40~0.45，ArcFace 0.50 → 0.55~0.65）。

**进度条不动 / 没有进度条**
- v1.0.0 没有进度条，v1.0.1 加上了。执行期间会在「立即试用」下方显示阶段文字 + 进度条。

**换了识别模型，阈值要不要跟着改？**
- **不用手动改，也不能照搬**。余弦相似度的分布是跟着模型走的：SFace 官方推荐 **0.363**，
  InsightFace 的 ArcFace 系在 **0.4~0.6** 这一档（InsightFace 官方指南 1:N 示例以 0.40 起步、
  社区实践常用 0.60，本插件取 **0.50** 作起点）。拿 0.363 去跑 ArcFace 会偏宽松、更容易串脸。
- v1.2.1 起插件会**自动按当前模型取推荐值**，并且把你在各款模型下调过的值**分开记住**，
  切换模型不会互相污染。设置页阈值那一行下方会写明「当前模型 / 推荐值 / 你现在设的是多少」，
  旁边有「**恢复推荐值**」按钮。
- 设置里选的模型文件不在、插件回退到自带 SFace 时，阈值也会跟着回到 0.363（取的是**实际载入**的模型）。

**为什么不用更大更强的模型？**
需求是「8 GB 可运行的开源小模型 + 2 分钟内完成」。InsightFace 的 `buffalo_l` 精度更好，
但体积 326 MB、推理慢得多；`buffalo_sc` 里的 MobileFaceNet（13 MB）是个不错的折中，
本插件已经支持（见第二节的对比表），只是它**仅供非商业研究用途**，所以没有打进安装包。
就教室这个场景而言，**把分辨率提上去比换模型收益大得多**。

**隐私**
所有照片、特征向量、名单都只落在本机插件配置目录里；模型推理完全离线。
抓拍照片默认保留 14 天后自动清理，也可以在设置里关掉存档。
